Week 1 · Practical P1 · 2 hours

Problem tree, user groups and outcome indicators for your corridor

Objective

Define the transport problem of your corridor, identify the user groups it affects and set 5–7 measurable outcome indicators (LO1). This is the core of course-project Stage 1 (due Week 3).

Tasks

Task 1. Fix the corridor and its boundary

Name the corridor (street, section, interchange) agreed with the instructor. Sketch the study boundary on the LAB1 base map: the corridor itself, the area whose trips use it (about 400–800 m either side) and any parallel streets where effects could spill over. State the assessment year you will use for every alternative.

Deliverable: Boundary sketch with a two-line justification and the assessment year

Task 2. Build the problem tree

Write one core problem in one sentence that names who is affected, where and when, without naming a solution. Below it, list 3–5 causes; above it, 3–5 effects. Use the cycle-network tree from LEC1 as a model. Mark each box E (evidence you have), A (assumption) or ? (unknown).

Deliverable: Problem tree on one A4 page with each box marked E, A or ?

Task 3. Identify user groups

List the user groups and affected non-users of the corridor (for example pupils, older residents, people with disabilities, bus passengers, drivers, couriers, shopkeepers, residents living on the street). For each, state the main need and how the core problem affects them.

Deliverable: User-group table

User groupMain needHow the problem affects themEvidence (E/A/?)

Task 4. Turn the tree into objectives

Reverse the tree: each main effect becomes an objective (a direction of change). Keep 3–5 objectives. Check that at least one concerns accessibility, one safety and one fairness between user groups.

Deliverable: List of 3–5 objectives

Task 5. Define 5–7 outcome indicators

For each objective define one or two indicators. Prefer outcomes (effects on people) to outputs (system performance). Give each the unit, the data source and date you will use for the baseline, how often it should be measured, the desired direction, the user groups it can be split by, and the organisation that would own it. Use the Week 1 list of reusable Tashkent indicators where they fit.

Deliverable: Indicator table (5–7 rows), carried into Stage 1

Task 6. Test the indicators

Swap tables with another team. Check each indicator against the LEC2 criteria (relevant, measurable, baseline, target year, split by group, owner). Mark any indicator that only measures vehicles or only measures spending, and replace it.

Deliverable: Revised indicator table with one sentence on what you changed and why

Materials

  • LAB1 base map of your corridor (print or screen)
  • LEC1 problem-tree example
  • LEC2 indicator criteria
  • Pulatova (2024) walk index and survey items as a menu of indicators

Assessment

Continuous assessment (LO1): a problem statement free of solutions, a complete user-group table and 5–7 indicators that each have a data source, a baseline date and an owner.

Week 1 · Laboratory LAB1 · 2 hours · QGIS, Excel (QGIS 3.40 LTR or newer)

Base map of Tashkent and your corridor, with a dataset log

Objective

Map the city's districts, streets, public transport stops, metro stations and key destinations in QGIS, draw your corridor boundary, and record the source, date, coverage and limitations of every dataset you use (LO1, LO2).

Data

FileDescriptionSource
LAB01_base_map.gpkgLayers: city_boundary, districts (13; study_district = true for the 12 established districts), roads_main, roads_all, bus_stops, metro_stations, pt_routes, key_destinations (schools, universities/colleges, hospitals/clinics, markets/malls), pop_grid (Kontur H3 cells), example_corridor (Abdulla Qodiriy street ± 400 m)© OpenStreetMap contributors (ODbL); Kontur Population (2023)
LAB01_dataset_log.xlsxSheets: Dataset_log (source, date, licence, CRS, features, limitations — add your own rows), District_summary (COUNTIF/SUMIF formulas over the point tables), Corridor (example corridor indicators), Bus_stops, Metro, Destinations, Pop_grid, Corridor_pop (area-weighted population formulas)© OpenStreetMap contributors (ODbL); Kontur Population (2023)

All GIS layers use EPSG:32642 (WGS 84 / UTM zone 42N). Set the QGIS project CRS to EPSG:32642 before starting.

Steps

Step 1. Set up the project

  1. Project > New; Project > Properties > CRS: set EPSG:32642 (WGS 84 / UTM zone 42N)
  2. Layer > Add Layer > Add Vector Layer: open LAB01_base_map.gpkg and add all layers
  3. Districts: Layer Properties > Source > Query Builder: "study_district" = 1, so only the 12 study districts show
  4. Save the project as LAB01_<yourname>.qgz next to the data

Check: 12 district polygons are displayed; the bus_stops layer has 2,019 features

Step 2. Style the base map

  1. roads_main: Layer Properties > Symbology > Categorized on highway; give primary/trunk thicker lines
  2. bus_stops: small navy dots; metro_stations: red triangles; key_destinations: Categorized on category
  3. districts: no fill, grey outline; Labels > Single Labels on name_en

Check: Map resembles the LEC1 base map; four destination categories in the legend

Step 3. Count stops and destinations per district

  1. Processing Toolbox > Vector analysis > Count points in polygon: polygons = districts, points = bus_stops, field name NUMSTOPS
  2. Repeat for metro_stations and for key_destinations (use Select by Expression "category" = 'school' first and tick Selected features only)
  3. Open the attribute table and compare with columns D–F of District_summary in LAB01_dataset_log.xlsx
  4. In Excel, click a cell in column D and read its COUNTIF formula: it counts the District column of the Bus_stops sheet

Check: Your QGIS counts equal the workbook counts; city total 1,966 bus stops in the 12 study districts

Step 4. Check the population layer before you use it

  1. Vector geometry > Centroids: input pop_grid
  2. Vector general > Join attributes by location (summary): target = districts, join = centroids, predicate = contains, field = population, summary = sum
  3. Compare with column C of District_summary; then compare Olmazor and Yunusobod with the district populations quoted by Pulatova (2024): 387.7 thousand and 360.9 thousand in 2022
  4. Write the finding in the Known limitations column of the pop_grid row in Dataset_log

Check: Kontur gives Olmazor 74,918 and Yangi hayot 780,556 residents: the layer places Tashkent's population in the wrong districts and must not be used for district comparisons

Step 5. Map the example corridor and then your own

  1. Select by Location: bus_stops that are within example_corridor; read the count in the status bar; repeat for metro_stations and key_destinations
  2. Compare with the Corridor sheet (COUNTIF on the In example corridor columns)
  3. Layer > Create Layer > New GeoPackage Layer: my_corridor (Polygon, EPSG:32642). Digitise your corridor boundary; record its street name and width in attributes
  4. Repeat the Select by Location counts for my_corridor and add a column for your corridor in the Corridor sheet

Check: Example corridor: 5.49 km², 49 bus stops, 3 metro stations, 47 key destinations

Step 6. Complete the dataset log

  1. In Dataset_log, fill one row for every dataset you add (your corridor, field photos, any downloaded data): source, publisher, extract or capture date, licence, CRS, number of features, coverage and limitations
  2. Note at least one limitation per OSM layer (for example: mapped stops only, district boundaries from OSM)

Check: Every layer in your QGIS project has a row; the formula at the bottom counts the rows

Step 7. Print layout

  1. Project > New Print Layout: A3 landscape; Add Map, Legend, Scale Bar, North Arrow
  2. Add a text box: 'Data: © OpenStreetMap contributors (ODbL), Geofabrik extract 2026-10-21; Kontur Population 2023 (CC BY 4.0); corridor: own digitising, <date>'
  3. Layout > Export as PDF

Check: The map shows the corridor boundary, streets, stops, metro and key destinations with a source and date line
